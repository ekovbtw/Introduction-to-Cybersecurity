![[Pasted image 20260904145050.png]]
В Linux Block Devices являются блочными устройствами. Устройства хранятся в директории **/dev**. 
Блочные устройства принимают запись и чтение по блокам. Размер логического блока (512 байт, 4КБ, или больше) задается устройствами. Физический размер блока может отличаться от этого значения. **lsblk** - утилита просмотра блочных устройств (которые видит система). 
Традиционные названия блочных устройств:
1. dev/sda (dev/sdb) - sata, usb (некоторые виртуальные диски). Буква в конце указывает порядок обнаружения дисков системой. 
2. dev/vda (dev/vdb) - виртуальные диски (диски виртуальных машин). Буква в конце по аналогии ставится как с SCSI (выше). 
3. dev/nvme0n1 (dev/nvme1n1) - NVME-накопители. nvme0 - контролер (на материнской плате), n1 - номер диска (по аналогии выше). 
На блочном устройстве (его можно рассматривать, как полностью физический накопитель) есть независимые области, поэтому существует разбиение на разделы. 
**Раздел** - непрерывная область на диске, запись о которой есть в таблице разделов (MBR или GPT). Раздел тоже считается блочным устройством (dev/sda1 или dev/nvme0n1p1). Цифра в конце номер раздела. 

В MBR существует три типа разделов: 
1. Основной раздел - базовый раздел диска (до 4 штук)
2. Расширенный раздел - специальный основной раздел, служащий контейнером для логических разделов
3. Логический раздел - используется как обход лимита создания основных разделов (4шт) путем создания разделов внутри расширенного. 
В терминологии GPT нет таких ограничений (соответственно не используется разграничение разделов)

После создания раздела идет форматирование (оно определит, каким образом будут хранится файлы, искаться и восстанавливаться). 
В GNU/Linux самые распространенные это: 
1. **ext4** - Стандартный формат для большинства дистрибутивов: root-разделы, обычные серверы, рабочие станции - Преимущества: простая, стабильная, хорошо поддерживается. Записывает в журнал метаданные (вплоть до полных), что помогает восстанавливать данные. Нет снапшотов и сжатия. 
2. **XFS** - Серверы, большие хранилища, крупные файлы - Хорошо работает с большими данными, умеет увеличиваться без размонтирования, но не может уменьшаться. 
## **Другие файловые системы**
**ZFS** (Zettabyte FS) - мощная файловая система, работающая поверх файловой системы, а диски  объединяет в пул хранения. Работает по принципу Copy-on-Write. Использует транзакции (все изменения атомарны (либо применяются полностью, либо отменяются полностью при сбое)).  Требует много ОЗУ. 
**Принцип CoW (Copy-on-Write)** - работает так, что при изменении файла, система не трогает старые блоки, а записывает новые в другое место, только потом обновляет метаданные. Таким образом, при сбоях питания, старые и новые данные не потеряются. Также можно мгновенно делать снапшоты. 
**NFS** (Network FS) - сетевая ФС (не дисковая). Позволяет монтировать удаленную директорию, как локальную, обеспечивая сетевой доступ между Linux/Unix - системами. 
*NTFS будет рассматриваться позже*. 
## Добавляем диск для хранения данных проекта
Создадим раздел, отформатируем его в файловую систему ext4, смонтируем и разберём основные действия по обслуживанию файловой системы.
### **Добавление диска**
На физическом сервере для этого обычно подключают новый накопитель: HDD, SSD или другой носитель данных. После подключения операционная система должна обнаружить новое устройство. В этом кейсе вместо физического накопителя добавим виртуальный диск через настройки гипервизора. Для этого выключим виртуальную машину, откроем её настройки и создадим дополнительный диск.

![[Pasted image 20260904153558.png]]
Pre-allocate сразу же выделит назначенную память на диске, без этой опции виртуальный диск будет расти до обозначенного значения по мере заполнения в нем данных. 
![[Pasted image 20260904153720.png]]
### **Создание раздела**
После добавления диска нужно создать раздел (логическую область диска), так как устройство не знает как его использовать. Разделы можно создавать для разных целей (хранения ОС, пользовательских данных и так далее). Для разметки есть несколько утилит: fdisk, parted, cfdisk. Они отличаются интерфейсом и возможностями: 
1. fdisk - классическая утилита для работы с таблицами разделов MBR и GPT. 
2. cfdisk - псевдографический интерфейс в терминале. 
3. parted - интерактивный/неинтерактивный режим. 

Внутри **fdisk** нас встретит интерактивное меню. Вот основные команды внутри него:
- **m** — показать список доступных команд;
- **p** — показать текущую таблицу разделов;
- **n** — создать новый раздел;
- **d** — удалить раздел;
- **t** — изменить тип раздела;
- **w** — записать изменения на диск;
- **q** — выйти без сохранения изменений.

### **Создание файловой системы**
Далее нужно раздел отформатировать, чтобы на нем хранить файлы. **mkfs** (make FS) - утилита для создания файловой системы. На самом деле это обертка, которая вызывает конкретную утилиту для конкретной файловой системы. 
**mkfs.ext4** - для ext4 файловой системы. 
**mkfs.xfs** - создает xfs файловую систему. 
Метка - удобное имя для диска. Чтобы отформатировать вместе с меткой используем: 
`sudo mkfs.ext4 -L mydata /dev/sdb1`. 
### **Монтирование файловой системы**
Файловая система создана, но диск нужно примонтировать к определенной точке в дереве Linux. Так как в Linux все исходит от одного корня /.
Командой: `sudo mkdir /mnt/mydata` создадим директорию для монтирования диска.
Дальше командой: `sudo mount /dev/sdb1 /mnt/mydata` монтируем диск.
Теперь любая запись в /mnt/mydata физически окажется на новом диске. Также после окончания надобности диска его можно размонтировать командой: `sudo unmount /mnt/mydata`. Если кто-то работает в диске, то размонтировать его не получится. 
### **Изменение размера файловой системы**
В ext4 размер файловой системы можно изменить (если нужно больше места для проекта).  Увеличить размер ФС можно, если на диске есть свободное место (после раздела). Если раздел занимает весь диск, то сначала нужно расширить раздел, только потом файловую систему. Команда **resize2fs** (значение (5G))- редактирует размер ФС. При увеличении размера ФС не нужно размонтировать, но при уменьшении - нужно. **e2fsck** - проверяет ФС (с флагом -f принудительная проверка, даже если ФС - чистая). Если хотим занять максимально возможное место, то значение указывать не нужно. 
### **Проверка и восстановление файловой системы**
Проверка дисков - **fsck** используется в разных случаях (повреждение файлов, диска, неправильное выключение и так далее). Перед проверкой ФС нужно размонтировать (так как могут изменятся данные и метаданные во время проверки, что приведет к большим потерям). 
`sudo fsck.ext4 -n /dev/sdb1` - проверка без изменений, покажет только ошибки (-n no только чтение)
`sudo fsck.et 4 -p /dev/sdb1` - проверка с автоматическим исправлением ошибок (-p preen с исправлениями)
## LVM (Logical Volume Manager)
Решает следующую проблему: когда на sda место закончилось, а не sdb свободного места много, нет возможности предоставить свободное место диску sda (так как мы ограничены физическими носителями). LVM добавляет промежуточный слой между физическими дисками и файловыми системами. 
![[Pasted image 20260904205056.png]]
PV (физический том) - блочные устройства (разделы или целые диски), которые мы отдаем под управление LVM. 
VG (группа томов) - "общий пул" пространства, собранный из одного или нескольких PV. Все PV в группе объединяют свое свободное место.
LV (логический том) - "виртуальный раздел", который мы нарезаем из VG. На этом этапе создаем файловую систему, система видит LV как обычное блочное устройство. 
Благодаря такой можно: 
1. Объединить несколько физических дисков в один
2. Легко менять размер логических томов - просто добавляем или забираем место из общего пула 
3. Добавлять новые VG диски на лету
4. Создавать снимки дисков по принципу Copy-on-Write

## RAID
Помимо LVM существует еще один способ объединения дисков - RAID (избыточный массив независимых дисков). Идея в том, чтобы несколько накопителей объединить в один логический диск, который ОС видит как блочное устройство. 
LVM - для гибкого управления дисковым пространством (объединение, разделение, увеличение)
RAID - для повышения надежности хранения данных за счет избыточности (или скорости)
На практике их используются вместе: поверх RAID-массива накладывают LVM. 
### **Реализации RAID**
1. Программный RAID - массив обнаруживается драйвером MD в ядре Linux, а утилита mdadm используется для его создания, настройки и обслуживания. Вычисления выполняет процессор сервера. 
2. Аппаратный RAID - используется отдельный RAID-контроллер со своим процессом и памятью. Разгружает CPU, стоит денег и привязан к контроллеру. 
3. Интегрированный (Fake RAID) - разновидность программного RAID, которую настраивают через меню прошивки материнской платы или контроллера. 
В Linux чаще используют программный RAID. 
### **Уровни RAID**
**RAID 0 (striping, чередование)** - данные пишутся блоками поочерёдно на все диски.
![[Pasted image 20260905003143.png]]
Плюсы: возможное повышение производительности за счет параллельной записи на диски. Полный объем = сумме всех дисков
Минусы: выход из строя любого диска = уничтожение всего массива
Применение: временные данные, где важна скорость, а не надежность (кэш)

**RAID 1 (mirroring, зеркалирование)** - одни и те же данные полностью дублируются на двух (или более) дисках.
![[Pasted image 20260905003419.png]]
Плюсы: при отказе одного диска система работает дальше. Высокая скорость чтения.
Минусы: Занимает в два раза больше места. 
Применение: БД, системные файлы, везде где нужна надежность

**RAID 5** - данные и блоки чётности распределены по всем дискам массива.
![[Pasted image 20260905003602.png]]
Плюсы: выдерживает отказ одного диска. Эффективно использует пространство. 
Минусы: Минимум 3 диска. Перестройка массива при замене диска занимает много времени. 
Суть: для каждой полосы данных вычисляется блок чётности. В RAID 5 он формируется операцией XOR над блоками данных этой полосы. Например, если у нас 3 диска с блоками **a**, **b** и блоком чётности **c = a XOR b**, то при отказе любого диска мы можем восстановить его, выполнив XOR оставшихся двух. Если откажет **a**, то **a = b XOR c**.
**Ёмкость:** (N-1) × размер наименьшего диска, где N - количество дисков.

**RAID 6** - аналог RAID 5, но с двумя независимыми блоками чётности.
![[Pasted image 20260905003934.png]]
**Плюсы:** выдерживает отказ **двух** дисков одновременно.
**Минусы:** минимум 4 диска. Ещё больше накладных расходов на вычисления.
**Ёмкость:** (N-2) × размер наименьшего диска, где N - количество дисков.
## Работа с LVM и RAID
На диске **/dev/sdb** уже есть раздел **/dev/sdb1** с файловой системой ext4. Для создания RAID нам нужно использовать диски целиком (без разделов), поэтому сначала удалим раздел: **sudo fdisk /dev/sdb**
### **Создаём RAID 1 с помощью mdadm**
Теперь создадим RAID 1 из двух дисков (**/dev/sdb** и **/dev/sdc**). RAID 1 обеспечит надёжность: если один диск выйдет из строя, данные сохранятся на другом.
Устанавливаем mdadm и создаем массив: `sudo apt install mdadm -y`, 
затем `sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc`
Разберём команду:
- **--create /dev/md0** - создать новый массив **/dev/md0**
- **--level=1** - уровень RAID 1
- **--raid-devices=2** - количество активных устройств (2 диска)
- **/dev/sdb /dev/sdc** - сами диски
Проверим состояние массива: `cat /proc/mdstat`
Посмотрим подробную информацию о массиве: `sudo mdadm -D /dev/md0`
В RAID 1 доступный объём равен объёму одного диска, а не сумме. Второй диск используется для зеркалирования.
Сохраним конфигурацию массива, чтобы он автоматически собирался при загрузке: `sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf`
### **Создаём LVM поверх RAID**
Создадим на RAID-массиве LVM для гибкого управления пространством.
**Создаём Physical Volume (PV)**
Сначала инициализируем **/dev/md0** как физический том LVM: установим пакет **lvm2** командой `sudo apt install lvm2 -y`, а затем создадим диск командой `sudo pvcreate /dev/md0`
Проверим созданный PV: `sudo pvs`
**Создаём Volume Group (VG)**
Теперь создадим группу томов **vg_data**, в которую добавим наш PV: `sudo vgcreate vg_data /dev/md0`
Проверим VG: `sudo vgs`
**Создаём Logical Volume (LV)**
Создадим логический том **lv_projects** размером 1 ГБ: `sudo lvcreate -L 1G -n lv_projects vg_data`
Разберём команду:
- **-L 1G** - размер тома (1 гигабайт)
- **-n lv_projects** - имя тома
- **vg_data** - группа томов, из которой берём пространство
Проверим созданный LV: `sudo lvs`
Теперь у нас есть логический том **/dev/vg_data/lv_projects**, который можно использовать как обычный раздел.
**Создаём файловую систему и монтируем**
Создадим на логическом томе файловую систему ext4: `sudo mkfs.ext4 -L projects /dev/vg_data/lv_projects`
Создадим точку монтирования и примонтируем: `sudo mkdir /mnt/projects`, теперь `sudo mount /dev/vg_data/lv_projects /mnt/projects`
Такое монтирование временное: после перезагрузки файловая система не будет подключена автоматически.
### **Расширяем логический том**
Одно из главных преимуществ LVM - возможность легко менять размер томов. Допустим, нам нужно увеличить **lv_projects** до 1.5 ГБ.
Сначала увеличим сам LV: `sudo lvextend -L 1.5G /dev/vg_data/lv_projects`
Теперь нужно "растянуть" файловую систему, чтобы она заняла новое пространство: `sudo resize2fs /dev/vg_data/lv_projects`
> **Важно:** для ext4 файловую систему можно увеличивать без отмонтирования. Но уменьшать можно только отмонтированную ФС.

Проверим результат: `df -h /mnt/projects`
### **Создаём второй логический том**
sudo lvcreate -L 500M -n lv_backups vg_data
sudo mkfs.ext4 -L backups /dev/vg_data/lv_backups
sudo mkdir /mnt/backups
sudo mount /dev/vg_data/lv_backups /mnt/backups
