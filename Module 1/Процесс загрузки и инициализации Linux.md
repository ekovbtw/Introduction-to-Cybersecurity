## **Общая схема загрузки и инициализации**
1. Питание и POST (Power-on Self-test) - подача напряжения на оборудование и самодиагностика.
2. Прошивка (BIOS или UEFI) - поиск загрузочного устройства
3. Загрузчик (GRUB2) - выбор ядра, передача параметров ядру
4. Ядро Linux - инициализация драйверов и подсистем
5. initramfs - подготовка окружения, загрузка модулей и монтирование файловой системы
6. systemd - запуск сервисов по зависимостям (PID 1)
7. Targets - приведение системы к целевому состоянию 
8. Пользовательский уровень - запуск getty и дисплейного менеджера, вход в систему
## **Этап 1: Питание и самотестирование**
После подачи питания на материнскую плату, управление передается микрокоду - низкоуровневым инструкциям, зашитых в BIOS/UEFI. Этот микрокод выполняет POST: 
1. Работоспособность процессора 
2. Наличие и целостность ОЗУ 
3. Базовые контроллеры (диски, клавиатура и тд)
4. Корректность прошивки 
Если POST проходит успешно, система переходит к следующему этапу. POST - первый аппаратный фильтр, гарантирующий, что базовые компоненты исправны. 
## **Этап 2: Прошивка BIOS/UEFI**
После прохождения POST прошивка ищет загрузчик. 
BIOS работает по старому принципу: 
1. Читает первый сектор загрузочного диска - MBR (Master Boot Record)
2. Передает управление коду, который лежит в загрузчике
3. MBR запускает загрузчик 

UEFI работает по другому: 
1. Читает таблицу разделов GPT (GUID Partition Table) 
2.  Обращается к специальному EFI System Partition (ESP) - обычно это FAT32-раздел размером в несколько сотен МБ
3. Находит там .efi-загрузчик (например grubx64.efi)
4. Передает ему управление

Отличия BIOS/UEFI: 
1. Таблица разделов - MBR - GPT
2. Максимум разделов - 4 основных - до 128
3. Максимальный размер диска - 2 ТБ - не ограничено 
4. Загрузочный раздел - MBR - ESP(FAT32)
5. Поддержка Secure Boot - нет - да 
В современных машинах используется UEFI, но BIOS никуда не делся. Используется в ВМ, старых машинах. В Linux раздел ESP находится в /boot/efi или /efi. При такой схеме на ESP хранятся efi-файлы загрузчиков, а ядро Linux в каталоге /boot. Существуют и другие схемы. 

## **Этап 3: Загрузчик GRUB2**
В BIOS загрузчик GRUB2 загружается поэтапно: 
1. Stage 1 - запускает Stage 1.5 по конкретному сектору. (изначально код в MBR или файл .efi в ESP в жестко ограниченном пространстве). 
2. Stage 1.5 (core.img) - содержит драйверы файловых систем, чтобы найти Stage 2. 
3. Stage 2 - основной код загрузчика GRUB, лежит в /boot/grub. Отрисовывает меню, читает конфигурацию и запускает ядро. 

Задачи GRUB2: 
1. Показать меню выбора ОС (если их несколько). 
2. Выбрать нужное ядро Linux.
3. Передача ядру параметров загрузки. 
4. Загрузка в память образа intramfs.
С помощью параметров загрузчика также запускается rescue-режим (режим-спасения) для восстановления пароля root пользователя, если тот утерян. Конфигурация GRUB обычно лежит /etc/default/grub, а сам меню-файл генерируется утилитой grub-mkconfig и сохраняется в /boot/grub/grub.cfg.

Возможные параметры конфигурации следующие: 
1. GRUB_TIMEOUT - сколько секунд показывать меню.
2. GRUB_DEFAULT - какой пункт меню загружать по умолчанию. 
3. GRUB_CMDLINE_LINUX_DEFAULT - параметры для ядра.
4. GRUB_CMDLINE_LINUX - дополнительные параметры ядра.
5. GRUB_DISABLE_OS_PROBER - искать ли другие ОС. 

Параметры ядра позволяют повлиять на запуск ядра еще до его запуска. Например: 
1. quiet - скрытие подробного вывода ядра для чистого старта. 
2. splash - показывать графическую заставку вместо текста 
3. nomodeset - отключение ранней инициализации видеодрайверов (KMS). 
4. single - система загружается для администрирования в однопользовательском режиме. 
5. systemd.unit=rescue.target - явное указание systemd запустить rescue-target. 
6. rw init=/bin/bash - указание ядру запустить командную оболочку напрямую в качестве первого процесса, минуя systemd.
